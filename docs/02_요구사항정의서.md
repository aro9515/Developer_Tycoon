# 02. 요구사항 정의서

## 1. 문서 목적

원본 `Developer_Tycoon_Game_MVP_Requirements.md`를 **구현 가능한 요구**로 재정의한다.  
우선순위: **Must / Should / Could / Won’t (MVP)**

---

## 2. 이해관계자 & 성공 기준

| 역할 | 관심사 |
|------|--------|
| 플레이어 | 짧은 세션, 명확한 성장, “한 판 더” |
| 개발(우리) | 단일 플레이어, 로컬/간단 세이브, 웹 배포 |

### MVP 성공 기준
- [ ] 튜토리얼 없이 첫 프로젝트 완료까지 3분 이내 가능
- [ ] 연속 플레이 20분 동안 파산/막힘 없이 루프 유지
- [ ] 기술부채를 **의도적으로** 쌓았다가 갚는 선택이 1회 이상 유도됨
- [ ] 세로 모바일 360px 폭에서 주요 CTA 터치 가능

---

## 3. 기능 요구사항

### 3.1 Must (MVP 필수)

| ID | 요구 | 수용 기준 |
|----|------|-----------|
| F-01 | 새 게임 / 이어하기 | 로컬 세이브 1슬롯 이상, 새로고침 후 복원 |
| F-02 | 시간 진행 | 일시정지, 1x/2x 배속 |
| F-03 | 프로젝트 수주 | 시장에 노출된 의뢰 중 선택/수락 |
| F-04 | 직원 배치 | 진행 중 프로젝트에 직원 할당/해제 |
| F-05 | 프로젝트 단계 진행 | 개발→테스트→배포→유지보수 자동/반자동 |
| F-06 | 버그 발생 | 진행 중 버그 수치 증가, 결과에 반영 |
| F-07 | 기술부채 | 빠른 개발 선택 시 부채 증가, 이자/장애 연동 |
| F-08 | 수익/지출 | 계약금, 완료금, 급여, 임대료 정산 |
| F-09 | 직원 성장 | 배치 기술에 XP, 레벨/숙련도 상승 |
| F-10 | 사무실 확장 | 책상 구매로 수용 인원 증가 |
| F-11 | 랜덤 이벤트 | 주 N회 풀에서 발생, 선택지 1~2개 |
| F-12 | HUD | 자금, 날짜, 부채, 신뢰, 진행 프로젝트 |

### 3.2 Should (MVP+ / 바로 다음)

| ID | 요구 |
|----|------|
| F-20 | 연구 트리 (자동테스트, CI/CD 등) |
| F-21 | 직원 채용 면접(간단 카드 선택) |
| F-22 | 휴게실/회의실 등 시설 효과 |
| F-23 | 업계 랭킹(단순 점수) |
| F-24 | 버스팩터 경고 UI |

### 3.3 Could (후속)

| ID | 요구 |
|----|------|
| F-30 | 해외 지사 / 상장 / 투자 |
| F-31 | 경쟁 회사 AI |
| F-32 | 오픈소스·컨퍼런스 |
| F-33 | 콘솔/모바일 게임 개발 라인 |

### 3.4 Won’t (MVP에서 명시적 제외)

- 온라인 멀티, PvP, 실시간 채팅
- 음성, 복잡한 전투
- 풀 스토리 모드 / 장편 컷신
- 계정 서버 필수 로그인 (게스트 로컬 우선)

## 4. 비기능 요구사항

| ID | 항목 | 목표 |
|----|------|------|
| NF-01 | 해상도 | 360×640 ~ 430×932 세로 기준, 가로 태블릿은 레터박스 허용 |
| NF-02 | 성능 | 중저가 모바일 크롬 기준 30fps UI, 틱 연산 < 8ms |
| NF-03 | 용량 | 초기 번들 목표 < 5MB (아트 제외 시 코드+데이터) |
| NF-04 | 오프라인 | 설치/캐시 후 오프라인 플레이 가능(이상적), MVP는 온라인 로드 후 로컬 플레이 |
| NF-05 | 세이브 | localStorage 또는 IndexedDB, 자동저장 최소 1분/주요 액션 |
| NF-06 | 접근성 | 색만으로 상태 구분 금지(아이콘+텍스트), 터치 타겟 ≥ 44px |
| NF-07 | 언어 | 한국어 1차 |

## 5. 유저 스토리 (핵심)

1. **프리랜서로서** 나는 작은 웹사이트 의뢰를 수락하고, 혼자 개발을 끝내 계약금을 받고 싶다.
2. **팀장으로서** 나는 FE 강한 직원과 BE 강한 직원을 알맞게 배치해 성공률을 올리고 싶다.
3. **경영자로서** 나는 일정을 앞당기기 위해 부채를 지고, 나중에 리팩토링으로 갚고 싶다.
4. **CTO로서** 나는 트렌디한 스택과 안정 스택 중 회사 방향을 고르고 싶다.
5. **위기 관리자로서** 나는 금요일 배포 이벤트를 거절하거나 강행해 결과를 감수하고 싶다.

## 7. 가정 & 제약

- 엔진/스택은 미정 → 기획은 엔진 중립 (권장: Phaser/Pixi + React UI 또는 순수 Canvas)
- 멀티 세이브, 클라우드 동기화는 MVP 비범위
- “현실 고증”보다 **게임으로서의 읽기 쉬운 과장** 우선

---

## 8. 오픈 이슈 (기획 확정 필요)

1. 시간 단위: **1틱 = 1시간** vs **1틱 = 0.5일** (모바일 템포에 따라)
2. 플레이어 캐릭터를 직원처럼 배치하는가? (권장: YES, 초기 유일한 개발자)
3. 기술부채 UI를 숫자만 보여줄지, **부채 카드(태그)** 로 보여줄지 (권장: 카드)
