# 08. 밸런스

## 1. 밸런스 철학

1. **초반은 관대, 중반은 이자, 후반은 시스템 활용**
2. 한 스탯이 만능이 되지 않게 (스피드만 / 완벽만 너프)
3. 숫자는 주간 단위로 “읽을 수 있게” (한 주 손익이 보임)
4. 모든 수치는 **초안** — 플레이테스트로 `K_` 상수만 튜닝

## 5. 진행·버그·모드 배율

```
progressPerTick = basePower * matchScore * mode.progressMul * conditionMul
bugPerTick      = baseBug * mode.bugMul * (1 + DP/500) * (1 - qaFactor)
```

| mode | progress | bug | debt | burn |
|------|----------|-----|------|------|
| normal | 1.0 | 1.0 | 1.0 | 0 |
| speed | 1.3 | 1.4 | 1.8 | 0 |
| overtime | 1.6 | 1.6 | 1.2 | 1.5 |
| perfection | 0.7 | 0.5 | 0.4 | 0.3 |

`basePower` 예: 직원당 3~8 (스탯 스케일)

## 8. 경제 곡선 (주간 손익 감)

### 초반 (1인)
- 수입: 프로젝트  Splits
- 지출: 임대 50/월, 서버 10/주
- 목표: 첫 채용 전 현금 1500+

### 중반 (3~5인)
- 주 급여 800~1500
- MRR 100~300
- 이자로 DP가 안 보이면 **숨은 지출**처럼 장애비로 드러남

### 후반
- 연구·시설이 이자 깎아 “규모 경제” 성립
- 레거시 앵커 관리가 주 전략

## 12. 튜닝 체크리스트

플레이테스트마다 기록:
1. 첫 파산까지 평균 시간 / 비율
2. 멜트다운 경험 비율 (목표 40~60% 플레이어가 1회 경험)
3. “할 일 없음” 구간 초
4. 가장 많이 고른 모드 (한쪽으로 80%면 너프/버프)
5. 채용 후 2주 내 재파산 비율

상수 파일 분리 권장: `balance.json`
