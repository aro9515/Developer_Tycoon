# 06. 기술부채 시스템

> 본 게임의 **시그니처 시스템**.  
> “빠르게 성장할수록 이자가 붙는 대출”을 코드 세계에 옮긴다.

---

## 1. 왜 기술부채인가

원본 요구: 빠른 개발 → 버그↑, 유지보수↑, 장애↑

이것만 있으면 **디버프 숫자**에 그친다.  
아래처럼 확장해 **전략·서사·UI 훅**이 되게 한다.

---

## 2. 부채의 3층 구조

```
[1] Debt Points (DP)     … 총량 숫자 (이자 계산 원본)
[2] Debt Cards (태그)    … “무엇을” 잘못했는지 (플레이어가 읽음)
[3] Debt Heat (위험도)   … 장애/폭발 확률에 쓰는 온도
```

| 층 | 플레이어 경험 |
|----|----------------|
| DP | HUD에 `부채 128` |
| Cards | “결제모듈 스파게티”, “테스트 없음” 카드 목록 |
| Heat | 게이지 색이 노랑→주황→빨강 |

---

## 3. Debt Card 카탈로그 (독창 핵심)

각 카드는 `id, name, severity, tags, weeklyInterest, incidentWeight, clearCost`

| ID | 이름 | 생기는 상황 | 주간 이자 | 특별 효과 |
|----|------|-------------|-----------|-----------|
| TD-01 | 테스트 없음 | 테스트 스킵, 스피드 | DP +3% | 배포 장애 + |
| TD-02 | 스파게티 모듈 | 스피드 완료 카드 | +2% | 해당 모듈 수정 공수 + |
| TD-03 | 매직넘버 지옥 | 완벽주의 미사용 | +1% | 버그 수정 실패 확률 |
| TD-04 | 문서화 공백 | 버스팩터 1 유지 | +2% | 퇴사 시 폭발 배율 |
| TD-05 | 구버전 의존성 | 트렌드 하락 스택 방치 | +2% | 보안 이벤트 가중 |
| TD-06 | 복사붙여넣기 | 유사 프로젝트 연속 스피드 | +3% | 버그 전염(다른 프로젝트로) |
| TD-07 | 조용한 장애 | 모니터링 연구 없음 | Heat만 ↑ | 장애가 “늦게” 발견 |
| TD-08 | 핫픽스 누더기 | 장애를 야근으로만 수습 | +4% | BurnDebt 연동 |
| TD-09 | DB 직접조작 문화 | 구두쇠+급한 고객 | +3% | 데이터 사고 이벤트 |
| TD-10 | AI 생성 미검증 | AI 활용↑ + 리뷰↓ | +2% | 대성공 확률 −, 진행 + |

카드는 **프로젝트에 귀속**되거나 **회사 전역**일 수 있다.  
전역 카드(의존성, 문화)는 더 무섭다.

## 4. 발생 규칙

```
onFeatureSpeedComplete(card):
  addDebtCard(TD-02) with chance
  DP += base * difficulty

onSkipTest():
  addDebtCard(TD-01)

onFridayDeploy():
  Heat += 15

onEmployeeResign(busFactor==1):
  amplify cards with tag documentation
  DP *= 1.3
```

---

## 5. 이자 (Interest) — “방치의 공포”

매 주 정산:
```
interest = floor(DP * interestRate)
interestRate = 0.03 + 0.01 * numSevereCards + facilityModifier + researchModifier
DP += interest
Heat += f(interest, openIncidents)
```

- CI/CD 연구: interestRate −0.01
- 코드리뷰 연구: 신규 카드 발생률 −20%
- 서버실 미비: Heat 증가량 +

**의도**: 부채를 안 갚으면 **복리로 죽음**. 일찍 조금 갚는 플레이가 보상을 받음.

## 6. Heat & 장애 폭발

| Heat | 상태 | 효과 |
|------|------|------|
| 0~29 | 안정 | 일반 |
| 30~59 | 주의 | 장애 소규모, 진행 −5% |
| 60~79 | 위험 | 주 1회 장애 이벤트 보장에 가까움 |
| 80~100 | 임계 | **부채 폭발** 트리거 가능 |

### 부채 폭발 (Debt Meltdown)
1. 랜덤 프로젝트 1~N 중단
2. 신뢰 −, 자금 −(위약/복구)
3. 강제 선택지:
   - **긴급 리팩토링 주간** (수입 일시 정지, DP 대폭 −)
   - **땜질 수습** (단기 복구, TD-08 추가, 다음 폭발 더 큼)
4. 사무실 비주얼에 “불꽃/알람” 연출 (카이로소프트식 과장)

---

## 7. 상환 (리팩토링) 방법

| 방법 | 비용 | 효과 | 언제 |
|------|------|------|------|
| 리팩토링 할당 | 직원 공수 | 카드 1장 제거 or DP − | 평시 |
| 리팩토링 스프린트 | 프로젝트 슬롯 1 소비 | DP −대, Heat − | 위기 전 |
| 자동화 연구 | 자금+시간 | 이자↓, 발생률↓ | 중반 |
| 폐기 | 신뢰/자금 | 프로젝트 귀속 카드 삭제 | 레거시 정리 |
| 페어/문서화 | 공수 | TD-04 제거, 버스팩터↑ | 인재 리스크 시 |

UI에서는 부채 카드를 탭 → “누가 갚을지” 할당하는 **미니 배치**가 됨.

---

## 8. 다른 시스템과의 결합

```
기술부채 ──┬── 야근부채: 핫픽스 누더기
           ├── 버스팩터: 문서화 공백 폭발
           ├── 레거시 앵커: 방치 시 DP+
           ├── 트렌드: 구버전 의존성
           ├── 경제: 장애 복구비, 유지보수 MRR↓
           └── 연구: 이자/발생 억제
```

이 결합이 **독창성의 본체**. 부채를 고립된 게이지로 두지 않는다.

## 9. 플레이어 전략 원형 (Archetype)

| 빌드 | 플레이 | 리스크 |
|------|--------|--------|
| 스프린트 카우보이 | 스피드+야근, 이자 감당 | 중반 멜트다운 |
| 장인 스튜디오 | 완벽주의, 소량 수주 | 성장 느림, 자금 |
| 자동화 공장 | 연구 선투자 | 초반 빈약 |
| 레거시 청소부 | 유지보수·리팩터 특화 | 대형 신규 수주 약함 |
| 트렌드 서퍼 | 인기 스택만 | 메타 변동에 휘청 |

## 10. UX 카피 톤 (예시)

- “결제 모듈이 스스로 얽히기 시작했습니다.”
- “이자로 부채 +12. 누군가의 금요일입니다.”
- “버스팩터 1: 민수 님이 감기 기운을 느낍니다…”

숫자는 차갑게, 카피는 따뜻하고 얄밉게.

---

## 11. MVP 범위

**Must**: DP, Heat, 카드 5종 이상, 주간 이자, 리팩토링 할당, 멜트다운 1회 이상 구현  
**Should**: 카드 10종, 전역/프로젝트 구분, 연구 연동  
**Could**: 부채 시각화 맵(모듈 그래프)
