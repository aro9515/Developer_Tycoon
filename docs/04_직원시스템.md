# 04. 직원 시스템

## 1. 설계 목표

- 카이로소프트처럼 **얼굴·이름·성장**이 보이고
- 배치 퍼즐이 생기며
- **버스팩터 / 야근부채**로 “사람 관리”가 기술부채와 맞물린다

---

## 2. 직원 엔티티

### 2.1 기본 프로필
| 필드 | 설명 |
|------|------|
| id, name, portraitId | 식별/비주얼 |
| roleTag | Junior / Mid / Senior / Lead |
| salary | 주급 |
| morale | 사기 0~100 |
| stress | 스트레스 0~100 |
| stamina | 체력 0~100 |
| traits | 특성 0~2개 (긍정/부정) |
| stackXp | 기술별 숙련도 맵 |
| ownedSystems | 버스팩터용 “이 사람이 아는 모듈” |

### 2.2 능력치 (원본 10종 → 플레이용 재편)

원본: 코딩, DB, 인프라, FE, BE, AI, 커뮤니케이션, 집중력, 체력, 스트레스

**권장 구조**

| 구분 | 스탯 | 용도 |
|------|------|------|
| 생산 | Coding, Frontend, Backend, Database, Infra, AI | 프로젝트 요구 매칭 |
| 소프트 | Communication | 고객 응대, 요구변경 저항, 팀 시너지 |
| 상태 | Focus, Stamina, Stress, Morale | 매 틱 효율·퇴사·야근 |

> Focus는 “집중력”의 현재값(변동), Coding 등은 장기 성장 스탯.

**매칭 점수 예시**
```
match = Σ (required[skill] * employee[skill]) / Σ required
effective = match * focusFactor * staminaFactor * (1 - stressPenalty)
```

---

## 3. 플레이어 캐릭터

- 게임 시작 시 **유일한 직원 = 플레이어**
- 초기 스탯: Coding 중하, 스택 1~2개만
- 회사 규모가 커지면 “직접 코딩” 시간이 줄고 **경영 액션**(채용·연구·수주) 비중 ↑
- CTO 단계: 플레이어를 프로젝트에 넣으면 진행↑ but 경영 이벤트 대응력↓ (트레이드오프)

---

## 4. 채용

### 4.1 채용 시장
- 매주 후보자 2~5명 리프레시
- 카드: 스탯 요약, 희망연봉, 선호 스택, 특성

### 4.2 채용 제약
- 빈 책상(좌석) 필요
- 급여 여력 경고 (2주치 급여 < 현금이면 위험 표시)

### 4.3 특성 예시
| 특성 | 효과 |
|------|------|
| 깔끔한 코드 | 발생 부채부채 −15% |
| 스피드광 | 진행 +10%, 부채 +10% |
| 야근 거부 | 야근 명령 시 사기 −− |
| 버스맨 | ownedSystems 획득 2배 (위험↑) |
| 레거시 수호자 | 유지보수 효율 +25% |
| 트렌드 추종 | 인기 스택 XP + , 구식 스택 사기 − |
| 조용한 전문가 | Communication ↓, Coding ↑ |

---

## 5. 성장

| 경로 | 내용 |
|------|------|
| 프로젝트 XP | 배치된 요구 스택에 XP |
| 교육실 | 골드 소비, 특정 스택 집중 학습 |
| 멘토링 | Senior가 Junior와 같은 프로젝트면 Junior XP↑ |
| 연구 참여 | 연구 완료 시 관련 스탯 소폭↑ |

레벨업 시: 스탯 +1 선택 또는 랜덤, 급여 상승.

---

## 6. 독창 시스템 A — 버스팩터 (Bus Factor)

### 개념
특정 모듈/프로젝트를 **아는 사람 수**. 1명이면 위험.

### 규칙
- 직원이 프로젝트에서 일하면 `ownedSystems`에 해당 프로젝트 모듈 태그 축적
- `busFactor(project) = 해당 모듈을 아는 직원 수`
- 경고: busFactor == 1 이고 진행도 > 50% → HUD 경고
- **핵심 인력 퇴사/번아웃 시**:
  - 관련 프로젝트 기술부채 +대량
  - 유지보수 공수 +50%
  - “지식 복구” 미니 퀘스트 (문서화/페어) 발생

### 플레이 의도
사람을 갈아넣는 운영을 하면 **단기 이득, 장기 파산**.  
문서화 연구·페어 프로그래밍으로 버스팩터를 분산시키는 것이 중후반 전략.

## 7. 독창 시스템 B — 야근 부채 (Burn Debt)

기술부채와 **별개**인 “사람 쪽 부채”.

| 행동 | 효과 |
|------|------|
| 야근 모드 ON | 진행 +30~50%, 체력↓ 스트레스↑, **BurnDebt +** |
| BurnDebt 높음 | 버그 놓침↑, 퇴사 확률↑, 이벤트 “폭발” |
| 상환 | 휴가, 휴게실, 복지비, 강제 정상 근무 |

```
BurnDebt 이자(주간): +ceil(burnDebt * 0.05) 스트레스
임계치 돌파: "번아웃 연쇄" → 무작위 1~3명 병가
```

**디자인 포인트**: 기술부채를 안 쌓으려고 야근만 하면 **다른 게이지가 터진다**.

---

## 8. 사기·퇴사

### 사기 변화 요인
- + : 성공 보너스, 복지, 휴게실, 트렌디 스택 사용, 승진
- − : 야근, 실패, 낮은 연봉, 구식 스택 강제, 회의 폭증

### 퇴사 판정 (주간)
```
resignChance = f(stress, morale, overworkWeeks, marketDemandForStacks)
```
퇴사 예고 1주 전 이벤트(“잔류 협상”: 연봉↑ or 프로젝트 변경).

---

## 9. 역할과 배치 슬롯

프로젝트 카드에 권장 슬롯:
- FE / BE / Full / QA / DevOps / PM(커뮤니케이션)

슬롯 불일치 시 진행은 되나 효율↓, 부채↑.  
QA 미배치 시 테스트 단계 버그 잔존↑.

---

## 10. MVP 범위

**포함**: 플레이어+채용, 스탯, 배치, XP, 급여, 스트레스/사기, 퇴사, 버스팩터(기본), 야근부채(기본)  
**제외**: 상세 스킬트리, 연애/인간관계 그래프, 세밀한 면접 미니게임
