# 07. 경제 시스템

## 1. 목표

- 현금 흐름이 **매 주 긴장**을 만든다
- “큰 계약”만 쫓으면 고정비·부채·유지보수에 무너진다
- **신뢰**가 돈 다음의 두 번째 화폐

---

## 2.  Dual Currency (사실상)

| 자원 | 성격 | 주요 획득 | 주요 소비 |
|------|------|-----------|-----------|
| **Cash** | 하드 | 착수금, 잔금, MRR | 급여, 임대, 서버, 복지, 연구 |
| **Trust** | 소프트 | 성공/대성공, 장애 신속 대응 | 실패, 방치, 멜트다운 |
| **Company Value** | 점수 | 자산·신뢰·인력·완료작 | 파산·대량퇴사 시 ↓ |

랭킹/엔딩은 Company Value 중심.

---

## 3. 수입

### 3.1 프로젝트
| 항목 | 타이밍 | 비율 초안 |
|------|--------|-----------|
| 착수금 | 수락 시 | 예산의 30% |
| 잔금 | 완료 시 | 결과 배율 × 70% |
| 위약금(실패) | 실패 시 | 0 또는 − (고객 성격) |

### 3.2 유지보수 MRR
- 레거시 앵커 프로젝트당 주간 소액
- 부채 Heat 높으면 MRR − (고객 불만)
- “유지보수 계약 업셀” 이벤트 → MRR↑, 공수↑

### 3.3 기타 (Should)
- 긴급 핫픽스 외주
- 컨설팅(커뮤니케이션 높은 직원)

---

## 4. 지출

| 항목 | 주기 | 메모 |
|------|------|------|
| 급여 | 주간 | 역할·레벨 비례 |
| 임대료 | 월간 | 사무실 티어 |
| 서버비 | 주간 | 서버실 시설·동시 프로젝트 |
| 라이선스 | 월간 | 연구/스택에 따라 |
| 복지 | 임의 | 사기↑, BurnDebt↓ |
| 채용비 | 채용 시 | 사이닝 보너스 |
| 연구비 | 연구 시작 | 일시금 or 할부 |
| 장애 복구 | 이벤트 | Heat 연동 |

### 파산 규칙
```
if cash < 0:
  graceDays = 3
  during grace: 진행 가능, 채용/확장 잠금, 신뢰 서서히↓
  if still < 0 after grace: Game Over
```

---

## 5. 신뢰 (Trust) 시스템

| 구간 | 이름 | 효과 |
|------|------|------|
| 0~19 | 無名 | D~C 티어만 |
| 20~39 | 동네업체 | C 안정, B 가끔 |
| 40~59 | 전문팀 | B 해금, 착수금 조건 완화 |
| 60~79 | 신뢰브랜드 | A 해금, 지원자 질 ↑ |
| 80~100 | 업계명성 | S 해금, 경쟁입찰 승리 보정 |

신뢰는 **쉽게 떨어지고 천천히 오른다** (카이로소프트 명성 감각).

---

## 6. 회사 가치 산출 (초안)

```
Value = cash * 0.2
      + sum(employeeMarketValue)
      + sum(completedProjectPrestige)
      + trust * 50
      + facilityValue
      - DP * 3
      - burnDebt * 2
```

부채가 가치에서 빠지므로 “외형만 큰 회사”는 랭킹이 안 오른다.

## 7. 가격표 초안 (절대값은 `08_밸런스`에서 조정)

|------|--------|

---

## 8. 독창 연동 — “겉성장 함정”

빠른 수주 → 착수금으로 채용 → 고정비↑ → 스피드로 납품 → DP↑ →  
MRR↓·장애↑ → 급여일 파산.

이 **함정 루프**를 초반 이벤트/툴팁으로 한 번 가르쳐 주면,  
기술부채 시스템이 경제적으로도 의미를 갖는다.

---

## 9. MVP 범위

**포함**: Cash, Trust, 착수/잔금, 주간 급여, 임대, 서버, 파산 유예, Value 산출  
**Should**: MRR 업셀, 라이선스  
**제외**: 주식/상장, 실제 세금 시뮬레이션, 다통화
