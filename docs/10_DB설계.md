# 10. DB 설계

## 1. 저장 전략 (MVP)

| 방식 | 용도 |
|------|------|
| **런타임 메모리** | 시뮬레이션 상태 |
| **IndexedDB 또는 localStorage** | 세이브 스냅샷 JSON |
| **정적 JSON** | 프로젝트 템플릿, 이벤트, 스택, 밸런스 상수 |

서버 DB 없음. 아래는 **논리 스키마** (= 세이브/마스터 데이터 구조).

---

## 2. ER 개요

```
GameSave
 ├── Company
 ├── PlayerSettings
 ├── Employees[]

 ├── DebtCards[]
 ├── Facilities[]
 ├── ResearchState[]
 ├── MarketOffers[]

```

## 5. 마이그레이션

- `version` 증가 시 `migrate(save)` 순차 적용
- 모르는 필드는 무시, 필수 필드 없으면 기본값
- MVP: 슬롯 1, 깨지면 “손상된 세이브” + 뉴게임

---

## 6. 인덱스/성능 메모

- 틱마다 전체 JSON stringify는 부담 → **더티 플래그** 시 저장, 또는 1분 스로틀
- 직원·프로젝트 배열 N 작음 (수십) → DB 정규화 불필요
- 이벤트 히스토리는 최근 30개만 유지
