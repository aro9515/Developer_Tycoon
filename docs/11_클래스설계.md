# 11. 클래스 설계

## 1. 아키텍처 개요

엔진 중립. 권장 분리:

```
UI (React/HTML)  ←→  GameFacade  ←→  Simulation Core
                         ↑
                   SaveService / DataCatalog
```

- **Simulation Core**: 순수 TS 권장 (DOM 없음) → 테스트 용이
- **UI**: 구독(스냅샷)만, 규칙 계산 금지

---

## 2. 핵심 클래스 / 모듈

### 2.1 Game
```
Game
- clock: GameClock
- company: Company
- staff: StaffManager
- projects: ProjectManager
- debt: DebtSystem
- market: MarketSystem
- events: EventSystem
- research: ResearchSystem
- facilities: FacilitySystem
- trends: TrendSystem
- economy: EconomySystem
+ tick(dt)
+ serialize() / deserialize()
```

### 2.2 GameClock
- `tick`, `day`, `week`, `speed`, `paused`
- `onDayEnd`, `onWeekEnd` 콜백 허브

### 2.3 Company
- 자원: cash, trust, value
- `addCash`, `spend`, `canAfford`
- stage / slots

### 2.4 Employee / StaffManager
- Employee: stats, condition, stacks, traits, assign
- StaffManager: hire, fire/resign, weeklyPayroll, updateConditions
- BusFactorService: `getBusFactor(projectId)`, `onResign`

### 2.5 Project / ProjectManager
- Project: state machine, progress, bugs, mode, featureCards
- ProjectManager: accept, tickAll, deliver, toMaintenance
- MatchScoreCalculator

### 2.6 DebtSystem (시그니처)
```
DebtSystem
- cards: DebtCard[]
- addFromAction(action)
- weeklyInterest()
- updateHeat()
- assignRefactor(cardId, employeeId)
- tryMeltdown()
```

### 2.7 EconomySystem
- settleAdvance / settleDelivery
- weeklyCosts
- calcCompanyValue
- bankruptcyGrace

### 2.8 MarketSystem
- refreshWeeklyOffers
- rollTemplate(trust, stage)

### 2.9 EventSystem
- evaluateDaily()
- applyChoice(eventId, choiceId)
- conditionMatchers (heat, dayOfWeek, flags)

### 2.10 TrendSystem
- popularity map
- onFrameworkEvent()
- modifierFor(stackId)

### 2.11 ResearchSystem / FacilitySystem
- unlock flags → modifiers를 ModifierBus에 등록

### 2.12 ModifierBus (추천)
연구·시설·이벤트 버프를 한곳에서 조회:
```
get(key: 'interestRate' | 'progressMul' | ...): number
```

## 3. 상태 머신

`ProjectStateMachine`
```
transitions:
  Contracted -> InDev (hasAssignee)
  InDev -> InTest (progress>=100 or forced)
  InTest -> Deploying
  Deploying -> Done | InDev (critical bug)
  Done -> Maintenance
  * -> OnHold / Failed
```

---

## 4. 데이터 흐름 (1틱)

```
Game.tick:
  clock.advance
  if paused: return
  projects.tick (progress, bugs, debt triggers)
  staff.tickConditions
  debt.updateHeat
  if dayEnd: events.evaluateDaily
  if weekEnd:
    economy.weekly
    debt.weeklyInterest
    market.refresh
    staff.resignCheck
    trends.drift
  notify UI snapshot
```

---

## 5. UI 바인딩

```
GameFacade
- getSnapshot(): Readonly<GameSnapshot>
- dispatch(action: GameAction)
```

`GameAction` 예:
- `ACCEPT_OFFER`, `ASSIGN_EMPLOYEE`, `SET_MODE`, `REFACTOR_CARD`
- `BUY_DESK`, `HIRE`, `CHOOSE_EVENT`, `SET_SPEED`

UI는 Action만 보냄 → 치트/버그 감소.
